# リリース手順

商城（微信小程序 / H5）・管理画面（PC）・API の 3 つを本番へ出すための手順です。

> **前提として時間がかかります。** 微信小程序の審査と各種の届出（备案）は、
> コードが完成していても **合計 1〜2 か月** かかることがあります。
> 特に越境EC の通関備案は最長です。リリース日から逆算して着手してください。

## 全体像

| 成果物 | ビルド | 置き場所 | 公開のしかた |
| --- | --- | --- | --- |
| 微信小程序 | `apps/shop/dist/weapp` | 微信のサーバ | 開発者ツールからアップロード → 審査 → 公開 |
| 商城 H5 | `apps/shop/dist/h5` | 静的ホスティング / CDN | 独自ドメインで配信 |
| 管理画面 | `apps/admin/dist` | 静的ホスティング | 社内向け。IP 制限か VPN の内側に置く |
| API | `apps/api/dist` | サーバ（Node 実行環境） | HTTPS 必須 |

```
                    ┌─────────────────┐
  微信アプリ ───────▶│ 微信小程序      │──┐
                    └─────────────────┘  │
                    ┌─────────────────┐  │   HTTPS
  スマホブラウザ ───▶│ 商城 H5         │──┼──────────▶ API ──▶ PostgreSQL
                    └─────────────────┘  │             │
                    ┌─────────────────┐  │             │
  社内 PC ─────────▶│ 管理画面        │──┘             ├──▶ 微信支付
                    └─────────────────┘                └──▶ 海关（申告）
                                                        ▲
                                            支付通知 ────┘（微信 → API）
```

**支付通知は微信からサーバへの受信**です。API は外部から到達可能な
HTTPS エンドポイントを持つ必要があります。ここを塞ぐと入金が確定しません。

## リリースサーバの条件

### API サーバ

| 項目 | 最小 | 推奨 | 理由 |
| --- | --- | --- | --- |
| CPU | 2 コア | 4 コア | 決済通知の処理と通関申告のジョブが並行する |
| メモリ | 2 GB | 4 GB | Node + Prisma で 1GB 前後。ビルド時はさらに要る |
| ディスク | 20 GB | 40 GB | ログと申告ペイロードの保存 |
| Node.js | 18 LTS | 20 LTS | `fetch` を標準で使っている |
| PostgreSQL | 14 | 16 | `Json` 型と部分インデックスを使用 |

### ネットワーク・ドメイン

- **HTTPS 必須。** 微信小程序は HTTP のエンドポイントを一切呼べません。
  TLS 1.2 以上、証明書は正規の CA のもの（自己署名は不可）。
- **API のドメインは微信公众平台の「服务器域名」に登録が必要です。**
  登録できるのは月 5 回までなので、ドメインを頻繁に変えないでください。
- **支付通知の URL は外部から到達可能であること。**
  微信のサーバから POST が飛んできます。IP 制限をかける場合は
  [微信支付の IP 範囲](https://pay.weixin.qq.com) を許可してください。
- API と商城 H5 は**別ドメイン（またはサブドメイン）**を推奨します。
  同一にすると、静的配信の設定ミスで API が落ちる事故が起きます。

### 設置場所

| 主な利用者 | 設置場所 | 注意 |
| --- | --- | --- |
| 中国本土 | 中国本土 or 香港 | 本土に置くなら **ICP 备案が必須**。無いとドメインが遮断される |
| 中国本土（本土サーバを避けたい） | 香港・シンガポール | 备案不要だが、本土からの遅延が 100〜300ms 増える |

> **ICP 备案について**
> 中国本土のサーバでドメインを公開するには工信部への届出（ICP 备案）が要ります。
> 通常 2〜3 週間、事業者の実体確認が入ります。
> **さらに 2023 年 9 月以降、微信小程序そのものにも备案が必要**になりました
> （後述）。サーバの备案とは別手続きです。

### データベース

- 本番は**マネージド DB を推奨**します（自動バックアップと PITR のため）。
- **暗号化した身分証番号を保存します。** 保存時暗号化（at-rest）を有効にし、
  バックアップの保管場所も含めてアクセス権を絞ってください。
- 接続は TLS で。`DATABASE_URL` に `?sslmode=require` を付けます。

### 秘密情報の管理

以下は **`.env` にベタ書きせず**、KMS / Secrets Manager から注入してください。
`.env` はリポジトリに含まれません（`.gitignore` 済み）。

- `WECHAT_APP_SECRET`
- `WECHAT_API_V3_KEY`
- 商户 API 秘密鍵（`apiclient_key.pem`）
- `JWT_SECRET` / `ENCRYPTION_KEY` / `HASH_PEPPER`
- `ADMIN_PASSWORD`

> **`ENCRYPTION_KEY` と `HASH_PEPPER` を失うと復旧できません。**
> 前者を失うと保存済みの身分証番号が復号できなくなり、通関申告が出せなくなります。
> 後者を変えると年間購入限度額の集計が過去分と繋がらなくなります。
> 生成したら**すぐに安全な場所へ退避**してください。

## 事前に取得が必要なもの

コードとは別に、**申請して待つ時間**が必要なものです。

| # | 必要なもの | 申請先 | 目安 | 依存 |
| --- | --- | --- | --- | --- |
| 1 | 営業許可証（营业执照） | 中国の登記機関 | — | 法人設立済みなら不要 |
| 2 | **食品経営許可証**（食品经营许可证） | 地方市場監督管理局 | 2〜4 週 | 食品販売に必須 |
| 3 | 微信小程序アカウント（**企業主体**） | 微信公众平台 | 1〜3 日 | 1 |
| 4 | **小程序备案** | 微信経由で工信部 | 1〜20 営業日 | 3 |
| 5 | ドメイン + SSL 証明書 | ドメイン業者 | 1 日 | — |
| 6 | **ICP 备案**（本土サーバの場合） | 工信部 | 2〜3 週 | 5 |
| 7 | 微信支付 商户号 | 微信支付商户平台 | 3〜7 日 | 1, 3 |
| 8 | 跨境电商 企業備案 | 海关総署 | 2〜6 週 | 1 |
| 9 | 电子口岸 IC カード | 中国電子口岸 | 2〜4 週 | 8 |
| 10 | 保健食品批准文号（該当商品のみ） | 国家市場監督管理総局 | 数か月〜 | — |

> **10 が無い商品は「保健食品」として売れません。** 一般食品としてのみ販売でき、
> 疾病の予防・治療を示唆する表現は使えません。詳細は
> [README の法規制セクション](../README.md#法規制コンプライアンス)を参照してください。

## 1. API のリリース

### ビルド

```bash
npm ci
npm run build:api
```

`apps/api/dist` が生成されます。

### マイグレーション

**`migrate deploy` を使ってください。** `migrate dev` は開発用で、
差分があるとデータを消して作り直すことがあります。

```bash
cd apps/api
npx prisma migrate deploy
```

### 初回のみ：マスタデータ

`npm run seed` は**開発用**で、本番では実行しないでください
（`NODE_ENV=production` ならガードで止まります）。
本番では管理画面から商品を登録するか、投入用スクリプトを別途用意します。

ただし **HS コード別税率だけは先に入れる必要があります。**
未登録だと既定値（9.1%）で計算され、品目によっては税額がずれます。

### 起動

```bash
cd apps/api
NODE_ENV=production node dist/main
```

プロセス管理は systemd か PM2、コンテナなら Docker を使ってください。
**再起動時に自動で立ち上がる**ようにしておくこと。支付通知を取りこぼすと
入金が確定しません。

### 起動確認

```bash
curl -s https://api.example.com/api/categories | head -c 200
```

`{"code":0,...}` が返れば動いています。

> **本番では Swagger（`/api/docs`）が無効になります。** `NODE_ENV=production`
> のとき自動的に無効化されるので、公開されていないことを確認してください。

## 2. 管理画面のリリース

```bash
npm run build:admin
```

`apps/admin/dist` を静的ホスティングに置きます。

### 注意点

- **SPA なので、全パスを `index.html` に返す設定が必要です。**
  そうしないと `/orders` を直接開いたときに 404 になります。

  nginx の例:
  ```nginx
  location / {
    try_files $uri $uri/ /index.html;
  }
  ```

- **`/api` を API サーバへプロキシしてください。** 開発時は Vite が
  やっていた部分です。同一オリジンにすると CORS 設定が不要になります。

  ```nginx
  location /api/ {
    proxy_pass https://api.example.com/api/;
    proxy_set_header Host $host;
  }
  ```

  プロキシしない場合は、API の `CORS_ORIGINS` に管理画面のオリジンを
  追加してください。

- **管理画面は公開しないでください。** 商品価格・在庫・注文を書き換えられます。
  IP 制限、VPN、または Basic 認証を前段に置くことを推奨します。
  アプリ側のパスワード認証は最後の砦であって、唯一の防御にしないでください。

## 3. 微信小程序のリリース

微信小程序だけは**審査があり、自分のタイミングで公開できません。**

### 3-1. 事前準備（初回のみ）

#### アカウントの種別

**企業主体（企业）で登録してください。** 個人主体では微信支付を使えず、
物販もできません。

#### 类目（カテゴリ）の設定

微信公众平台 →「设置」→「基本设置」→「服务类目」

健康食品を売るには **「电商平台」または「食品」** 系の类目を選び、
**食品経営許可証**を提出します。类目が合っていないと審査で落ちます。

#### 小程序备案（2023 年 9 月から必須）

微信公众平台 →「设置」→「基本设置」→「备案」

サーバの ICP 备案とは**別の手続き**です。これが完了していないと
**公開できません**（開発版・体験版は使えます）。1〜20 営業日かかります。

#### 服务器域名の登録

微信公众平台 →「开发」→「开发管理」→「开发设置」→「服务器域名」

| 種別 | 設定する値 |
| --- | --- |
| request 合法域名 | `https://api.example.com` |
| downloadFile 合法域名 | 画像 CDN のドメイン |
| uploadFile 合法域名 | （画像アップロードを実装したら） |

- **HTTPS のみ**。`http://` は登録できません。
- **ICP 备案済みのドメインのみ**登録できます。
- **月 5 回まで**しか変更できません。慎重に。

### 3-2. ビルド

`apps/shop/config/index.ts` の本番 API URL を確認します。

```ts
// process.env.API_BASE_URL が無ければこちらが使われる
'https://api.example.com/api'
```

環境変数で上書きするのが確実です。

```bash
API_BASE_URL=https://api.example.com/api npm run build:weapp
```

`apps/shop/dist/weapp` が生成されます。

### 3-3. AppID の設定

`apps/shop/project.config.json` の `appid` を、取得した AppID に変えます。

```json
{
  "miniprogramRoot": "dist/weapp/",
  "appid": "wxXXXXXXXXXXXXXXXX"
}
```

> このファイルはリポジトリに含まれます。AppID は秘密ではありませんが、
> **AppSecret は絶対にここに書かないでください**（サーバ側の `.env` にのみ置く）。

### 3-4. アップロード

1. **微信開発者ツール**でプロジェクトを開く
   - ディレクトリは `apps/shop`（`project.config.json` がある場所）
   - `miniprogramRoot` の設定により `dist/weapp` が読まれます
2. 右上の「**上传**」をクリック
3. バージョン番号（例 `1.0.0`）と説明を入力
4. アップロード完了

### 3-5. 体験版で確認

微信公众平台 →「管理」→「版本管理」→「开发版本」

- 「**选为体验版**」を押す
- 「体验成员」に確認者の微信 ID を追加
- 実機で動作確認する

> **必ず実機で確認してください。** 開発者ツールと実機では、
> `wx.login` / `wx.requestPayment` / カプセルボタンの位置などの挙動が違います。
> 特に決済は実機でしか通しで確認できません。

### 3-6. 審査に出す

「开发版本」→「**提交审核**」

審査で聞かれることが多い点:

| 項目 | 準備すること |
| --- | --- |
| テストアカウント | 不要（微信ログインのため）。ただし試験用の商品は公開しておく |
| 資質証明 | 食品経営許可証をアップロード |
| 機能説明 | 「健康食品の越境EC」と明記 |
| 支付機能 | 商户号が紐づいていること |

**審査は 1〜7 営業日**。差し戻されたら理由を直して再提出します。

### 3-7. 公開

審査通過後、「审核版本」→「**发布**」→「全量发布」

段階的に出したい場合は「**分阶段发布**」を選ぶと、
1% → 10% → 50% → 100% と広げられます。**初回は段階公開を推奨**します。

### 3-8. 問題が出たら

「线上版本」→「**版本回退**」で 1 つ前のバージョンに戻せます。
戻せるのは**直前のバージョンのみ**です。

## 4. 商城 H5 のリリース

微信の外（スマホブラウザ）で使う版です。小程序が主なら省略できます。

```bash
API_BASE_URL=https://api.example.com/api npm run build:h5
```

`apps/shop/dist/h5` を静的ホスティングに置きます。

- 管理画面と同じく **SPA のフォールバック設定**が必要です。
- API が別オリジンなら、`CORS_ORIGINS` に H5 のオリジンを追加してください。
- H5 には微信ログインが無いため、**未ログイン状態で動きます**。
  注文まで通すには別の認証（SMS など）の実装が必要です。

## WeChat Pay の設定

**ここを間違えると入金が確定しません。** 順番に進めてください。

### 手順の全体像

```
1. 商户号を取得          （微信支付商户平台）
2. AppID と商户号を紐づけ （商户平台 → 产品中心）
3. APIv3 密钥を設定      （商户平台 → API安全）
4. API 証明書を取得      （商户平台 → API安全）
5. 支付通知 URL を設定   （このアプリの .env）
6. 実機で決済を通す
```

### 1. 商户号（mchid）の取得

[微信支付商户平台](https://pay.weixin.qq.com) から申請します。

- **企業主体**が必要です
- 営業許可証、法人の身分証、銀行口座が要ります
- 審査は 3〜7 営業日
- 完了すると **商户号（10 桁の数字）** が発行されます

→ `WECHAT_MCH_ID` に設定

### 2. AppID と商户号の紐づけ

商户平台 →「产品中心」→「**AppID 授权管理**」→「关联 AppID」

小程序の AppID を入力し、小程序側で承認します
（微信公众平台 →「微信支付」→ 確認）。

**これをしないと `wx.requestPayment` が「商户号与 AppID 不匹配」で失敗します。**

### 3. APIv3 密钥の設定

商户平台 →「账户中心」→「API 安全」→「**设置 APIv3 密钥**」

- **32 文字ちょうど**のランダム文字列を自分で決めます
- 生成例:
  ```bash
  openssl rand -base64 24 | head -c 32
  ```
- **設定後は表示されません。** 必ず控えてから設定してください

→ `WECHAT_API_V3_KEY` に設定

> この鍵は支付通知の復号に使います。間違っていると通知を復号できず、
> **入金が永久に確定しません**（注文が未払いのまま残ります）。

### 4. API 証明書の取得

商户平台 →「账户中心」→「API 安全」→「**申请 API 证书**」

証明書ツールの指示に従うと、以下が手に入ります。

| ファイル | 用途 |
| --- | --- |
| `apiclient_key.pem` | **商户 API 秘密鍵**。リクエスト署名に使う |
| `apiclient_cert.pem` | 証明書本体（このアプリでは未使用） |
| 証明書シリアル番号 | リクエストヘッダに入れる |

シリアル番号は商户平台の「API 证书」画面か、次のコマンドで確認できます。

```bash
openssl x509 -in apiclient_cert.pem -noout -serial
```

設定:

```bash
WECHAT_MCH_CERT_SERIAL=1234567890ABCDEF...
WECHAT_MCH_PRIVATE_KEY_PATH=/secure/path/apiclient_key.pem
```

> **秘密鍵の扱い**
> リポジトリに入れないでください（`.gitignore` 済み）。
> 本番では KMS / Secrets Manager から取得し、ファイルに置くなら
> 権限を `600`、所有者をアプリの実行ユーザーだけにします。
> この鍵が漏れると**第三者が加盟店として返金や送金を実行できます**。

### 5. 支付通知 URL

```bash
WECHAT_PAY_NOTIFY_URL=https://api.example.com/api/payment/wechat/notify
```

条件:

- **HTTPS 必須**
- **外部から到達可能**（微信のサーバから POST が来る）
- **クエリ文字列を付けない**（微信が拒否します）

このアプリは受け取った通知に対して次を行います。

1. **署名検証**（プラットフォーム証明書。自動で取得・キャッシュします）
2. AES-256-GCM で復号
3. **金額の突合**（通知額と注文額が違えば成立させない）
4. 冪等に処理（同じ通知が何度来ても結果が変わらない）

> 微信は通知が失敗すると**最大 15 回まで再送**します。
> 5 秒以内に応答しないと再送扱いになるため、通知処理は重くしないでください。

### 6. 越境決済（跨境支付）の場合

海外法人が加盟店になる場合は「**境外收单**」として契約します。

| 項目 | 内容 |
| --- | --- |
| 顧客の支払い | **人民元（CNY）建て** |
| 加盟店への入金 | 契約通貨（例: JPY） |
| 換算 | **微信支付／決済代行が精算時に確定** |

```bash
PAYMENT_PROVIDER=wechat_direct   # または sbps
```

> **アプリは人民元しか扱いません。**
> 入金通貨と換算レートは微信支付との契約事項で、精算時に確定します。
> アプリ側に設定項目はなく、画面にも外貨額は一切表示しません。
> （表示すると請求額と誤認されるため、意図的に出していません）

決済代行（SB ペイメントサービス等）を経由する場合も、小程序から見た
フローは変わりません（`prepay_id` → `wx.requestPayment`）。
`prepay_id` を発行する相手が代行会社に変わるだけです。

```bash
PAYMENT_PROVIDER=sbps
SBPS_MERCHANT_ID=...
SBPS_SERVICE_ID=...
SBPS_API_KEY=...
SBPS_API_ENDPOINT=https://...
```

### 設定できているかの確認

API を起動したとき、次の警告が**出ていなければ**設定は揃っています。

```
WARN [WechatPayService] WeChat Pay is not fully configured; payment endpoints will return 503.
```

出ている場合、決済エンドポイントは 503 を返します（アプリは起動します）。
判定は設定値の有無だけでなく、**秘密鍵ファイルの実在**まで確認しています。

### 決済まわりでよくある失敗

| 症状 | 原因 |
| --- | --- |
| `商户号与AppID不匹配` | 手順 2 の紐づけが未完了 |
| 署名エラー | シリアル番号が証明書と一致していない |
| 通知が復号できない | `WECHAT_API_V3_KEY` が商户平台の設定と違う |
| 通知が届かない | URL が HTTPS でない / 外部から到達できない / クエリ付き |
| 決済は成功するが注文が未払いのまま | 通知の署名検証に失敗している。API のログを確認 |

## 環境変数の一覧

`apps/api/.env` に設定します。`apps/api/.env.example` が雛形です。

### 必須

| 変数 | 説明 |
| --- | --- |
| `NODE_ENV` | `production` |
| `PORT` | 待ち受けポート |
| `DATABASE_URL` | PostgreSQL 接続文字列。`?sslmode=require` を推奨 |
| `CORS_ORIGINS` | 商城 H5・管理画面のオリジン（カンマ区切り）。プロキシ構成なら不要 |
| `JWT_SECRET` | `openssl rand -base64 48` |
| `ENCRYPTION_KEY` | `openssl rand -base64 32`（**紛失すると復旧不可**） |
| `HASH_PEPPER` | `openssl rand -base64 32`（**変更すると限度額集計が断絶**） |
| `ADMIN_PASSWORD` | 管理画面のパスワード。未設定だと管理 API は全て 401 |
| `WECHAT_APP_ID` | 小程序の AppID |
| `WECHAT_APP_SECRET` | 小程序の AppSecret |

### 決済（使う場合は全部必要）

| 変数 | 説明 |
| --- | --- |
| `WECHAT_MCH_ID` | 商户号 |
| `WECHAT_MCH_CERT_SERIAL` | API 証明書のシリアル番号 |
| `WECHAT_API_V3_KEY` | APIv3 密钥（32 文字） |
| `WECHAT_MCH_PRIVATE_KEY_PATH` | `apiclient_key.pem` のパス |
| `WECHAT_PAY_NOTIFY_URL` | 支付通知の受け口（HTTPS） |
| `PAYMENT_PROVIDER` | `wechat_direct` または `sbps` |

### 任意

| 変数 | 未設定時の動作 |
| --- | --- |
| `CUSTOMS_ENABLED` | `false` なら通関申告を行わない |
| `CUSTOMS_*` | 通関申告の設定一式 |
| `REDIS_URL` | 未使用（将来のキャッシュ用に予約） |
| `SENTRY_DSN` | エラー送信を行わない |

## ロールバック

### 微信小程序

微信公众平台 →「版本管理」→「线上版本」→「**版本回退**」

**戻せるのは直前のバージョンのみ**です。2 つ前には戻せません。
不安な変更は**段階公開**（1% から）で出してください。

### API

前のバージョンのプロセスに戻します。

**マイグレーションを伴う場合は注意してください。**
Prisma の `migrate deploy` は前方向のみで、自動では戻せません。
破壊的な変更（カラム削除・型変更）を含むリリースでは、

1. 先に「新旧どちらのコードでも動く」中間状態をリリースする
2. 数日運用して問題が無いことを確認する
3. 古いカラムを消すリリースを出す

の 2 段階に分けてください。1 回で消すと、ロールバックした瞬間に
API が起動しなくなります。

### 管理画面 / 商城 H5

静的ファイルなので、前のビルド成果物に差し替えるだけです。
CDN を使っている場合はキャッシュのパージを忘れずに。
